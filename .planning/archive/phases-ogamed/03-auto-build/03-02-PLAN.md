```go
func NewDefender(client ogamed.ClientInterface, stateMgr StateReader, db *sql.DB, cfg config.DefenderConfig, log *slog.Logger) *Defender {
    return &Defender{...}
}

func (d *Defender) Run(ctx context.Context) {
    interval := time.Duration(d.cfg.PollIntervalMs) * time.Millisecond
    for {
        jitter := time.Duration(rand.Intn(int(interval.Milliseconds()/2)+1)) * time.Millisecond
        select {
        case <-ctx.Done():
            return
        case <-time.After(interval + jitter):
            d.poll(ctx)
        }
    }
}
```

<context>
The builder worker follows the exact same poll-loop + StateReader DI pattern as the defender. The key differences:
1. Reads buildings/facilities instead of fleets/attacks
2. Calls BuildBuilding instead of SendFleet
3. Evaluates ROI across all planets to pick the best candidate
4. Checks construction slots via GetConstructions
5. No tracking table needed (OGame tracks construction state server-side)

Per RESEARCH.md pitfalls to handle:
- Energy deficit: must verify energy surplus before upgrading mines
- Full planets: skip if FieldsUsed >= FieldsTotal
- Construction slot: skip planets with active building construction
- Anti-detection: occasionally pick 2nd-best ROI (configurable, 5-10% of the time)
- Universe speed: always multiply production by cached speed from state manager

Building name → level mapping for ResourceBuildings struct fields:
- MetalMine → buildings.MetalMine
- CrystalMine → buildings.CrystalMine
- DeuteriumSynthesizer → buildings.DeuteriumSynthesizer
- SolarPlant → buildings.SolarPlant
- FusionReactor → buildings.FusionReactor
</context>

    ```go
    }
    ```

    3. NewBuilder constructor — same DI pattern as defender.

    4. Run(ctx) method — exact same poll loop pattern as defender (interval + jitter + select).

    5. poll(ctx) method — the core logic:
       a. Get all planets from state
       b. Get server speed from state
       c. Get research from state
       d. For each planet:
          - Skip if FieldsUsed >= FieldsTotal (log warning: "planet full")
          - Get constructions via client.GetConstructions
          - Skip if Building.ID != 0 (active construction)
          - Get resources, buildings, facilities from state
          - For each building ID in ROI-relevant buildings [1,2,3,4,12]:
            - Get current level from buildings struct
            - Get max level via resolveMaxLevel(buildingName, planetName)
            - Call CalculateROI
            - If viable (true returned), add to candidate list
       e. Sort candidates by ROIScore descending
       f. If candidates exist, pick best (or 2nd-best 7% of the time for anti-detection via math/rand)
       g. Call client.BuildBuilding(ctx, candidate.PlanetID, candidate.BuildingID)
       h. Record build event to build_events table
       i. Log the decision with planet, building, level, ROI score, cost

    6. resolveMaxLevel(buildingName, planetName string) int:
       - Check cfg.PlanetOverrides[planetName][buildingName]
       - If found, return it
       - Otherwise return cfg.MaxLevels[buildingName]
       - If neither found, return 0 (effectively disabled)

    7. buildingLevel(buildings model.ResourceBuildings, buildingID int) int:
       - Switch on buildingID to return the correct struct field
       - 1 → buildings.MetalMine, 2 → buildings.CrystalMine, etc.

    8. recordBuildEvent(ctx context.Context, result ROIResult) error:
       - INSERT INTO build_events (planet_id, building_id, building_name, from_level, to_level, cost_metal, cost_crystal, cost_deut, roi_score)
       - Log error but don't fail the build
