<!-- OGameX endpoint strategy from research -->
<!--
Key OGameX endpoint patterns for per-planet data:

1. Planet list: GET /overview → parse planet menu HTML widget
   - Selector: planet menu list items with data-planet-id, name, coordinate attributes
   - Moon planets listed separately with is-moon indicator

2. Resources: GET /overview?cp=<planetID> → parse resource bar HTML
   - OR: GET /ajax/resources?cp=<planetID> → JSON with resource values
   - Resource bar contains metal, crystal, deuterium, energy values

3. Resource buildings: GET /resources?cp=<planetID> → parse building levels from HTML
   - Each building has a technology item with data-technology="<id>" and level display

4. Facilities: GET /facilities?cp=<planetID> → parse facility levels from HTML
   - Same pattern as resource buildings

5. Ships: GET /shipyard?cp=<planetID> → parse ship counts from HTML
   - Technology items with ship counts

6. Defence: GET /defense?cp=<planetID> → parse defense counts from HTML
   - Same pattern as ships

Planet context: ALL per-planet requests MUST include ?cp=<planetID> query parameter.
Without it, OGameX uses server-side "current planet" state which is unreliable for a bot.

HTML parsing strategy: Use goquery CSS selectors, NOT regex.
OGameX is a Laravel/Blade app — HTML structure follows predictable patterns.
Each "technology item" (building/ship/defense) has:
- data-technology="<numeric_id>" attribute
- Level/count displayed in a child element
- Building level in a span or data attribute
-->

Create `internal/ogamex/parser.go` in package `ogamex`:

1. **Import `github.com/PuerkitoBio/goquery`** and `internal/model`, `internal/constants`.

2. **`parsePlanetList(body io.Reader) ([]model.Planet, error)`**:
   - Parse HTML with `goquery.NewDocumentFromReader(body)`
   - Find planet menu items: `doc.Find(".planet-list .planet-item")` or equivalent selector
   - For each planet item, extract:
     - `ID`: from `data-planet-id` attribute or href containing `cp=<id>`
     - `Name`: from `.planet-name` text or equivalent
     - `Coordinate.Galaxy, System, Position`: from coordinate text "[X:Y:Z]" parsed with `fmt.Sscanf`
     - `IsMoon`: check for moon CSS class or data attribute
     - `Diameter, FieldsUsed, FieldsTotal, TemperatureMin, TemperatureMax`: from data attributes or child elements
   - Return error with meaningful message if no planets found

3. **`parseResources(body io.Reader) (model.Resources, error)`**:
   - Parse HTML for resource bar values
   - Selectors: `#resources_metal`, `#resources_crystal`, `#resources_deuterium`, `#resources_energy` or `data-resource` attributes
   - Parse integer values from text content (strip commas/dots: OGameX may format numbers as "1,234")
   - Helper: `parseAmount(s string) int` that strips non-numeric chars and parses

4. **`parseResourceBuildings(body io.Reader) (model.ResourceBuildings, error)`**:
   - Find technology items: `doc.Find(".technology")` or `doc.Find("[data-technology]")`
   - Map building IDs from constants to model fields:
     - ID 1 → MetalMine, ID 2 → CrystalMine, ID 3 → DeuteriumSynthesizer
     - ID 4 → SolarPlant, ID 12 → FusionReactor, ID 22 → MetalStorage
     - ID 23 → CrystalStorage, ID 24 → DeuteriumStorage
   - Extract level from `data-level` attribute or `.level` text element
   - Use a map[int]*int for clean ID → field mapping

5. **`parseFacilities(body io.Reader) (model.Facilities, error)`**:
   - Same pattern as parseResourceBuildings but for facility building IDs
   - Map: 14→RoboticsFactory, 21→Shipyard, 31→ResearchLab, 34→AllianceDepot, 44→MissileSilo, 15→NaniteFactory, 33→Terraformer, 36→SpaceDock

6. **`parseShips(body io.Reader) (model.Ships, error)`**:
   - Same technology-item pattern
   - Map ship IDs to model fields: 202→LightFighter, 203→HeavyFighter, etc. (use constants)

7. **`parseDefence(body io.Reader) (model.Defence, error)`**:
   - Same pattern as parseShips for defense structures

8. **Helper `parseAmount(s string) int`**:
   - Remove all non-digit characters (commas, dots, spaces)
   - Parse as int, return 0 on error

9. **Helper `extractLevelFromTechItem(s *goquery.Selection) int`**:
   - Try `data-level` attribute first
   - Fall back to `.level` text parsing
   - Return 0 if not found
